01 · Principles

What every screen must do

Customers: “I can find the right professional and understand what is happening.” Workers: “This helps me get and manage my work.” Admins: “I can operate the marketplace safely.”

P1Clear before prettyOne primary action per screen. Plain words a Class-5 reader understands. Icon + text, never icon alone.
P2Explain whyShow why a worker is shown (distance, rating, verified, “booked before”), why a price is what it is (bill lines), and why a status changed (reason code).
P3One label = one enumRequest, booking, job and visit are separate lifecycles. Chips show the friendly label of exactly one backend status.
P4Three languages, same layouten / bn / hi at launch. Design at 360 dp with +40% text. Indic line-height ≥ 1.5. Support 200% font scale.
P5 · PRIVACY RULEContact only after selectionAddress, on-site contact and phone numbers are released only to the selected worker / customer, and stay visible until 7 days after completion. Before selection: locality, distance (0.5 km steps), first name. Identity data (ID document, PAN, bank) is always masked (XXXXXX4821); no Aadhaar uploads. No chat, no masked calling in MVP.ADR 0011 · LLD-008 D6 · security/03
P6Money is exactBackend computes every amount. Workers never type a final total. Show ₹ amounts in one format everywhere (see §6).
P7Works on bad networksSkeletons, retry, “will retry when online”. Online-only actions (check-in, start code, payment) are blocked offline, not queued.
P8Big targets48 dp minimum hit area for anything tappable, chips included. Primary buttons 52 dp tall, full width on mobile.
Every screen answers
  1. What is the user's goal?
  2. Most important information?
  3. Primary action?
  4. What happens after?
  5. What if it fails?
  6. What if there is no data?
  7. What shows while loading?
  8. What if they come back later?
  9. What is sensitive?
  10. What must never be confusing?

05 · Rules

Money, tap targets, design width

Money format (P25, ADR 0006)

API sends integer paise (amountMinor). App formats with Indian grouping, ₹ with no space, paise only when non-zero, Latin digits in en/bn/hi. Negative lines (advance, already paid) show as “− ₹99”.
